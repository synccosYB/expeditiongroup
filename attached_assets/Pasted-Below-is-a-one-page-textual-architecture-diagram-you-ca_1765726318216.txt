# Expedition Plus – 1-Page Architecture Diagram (Textual)

## SYSTEM OVERVIEW

**Expedition Plus** is a single web application with three layers:

```
[ Public Website ]
        ↓
[ Authentication & Roles ]
        ↓
[ Internal CRM + Client Portal ]
```

All operational data revolves around **Projects**.

---

## 1. ENTRY LAYER – PUBLIC WEBSITE (No Login)

```
/ (Public Marketing Page)
│
├─ Hero (Permit Expediting)
│   └─ Service Area: Orange, Rockland & Sullivan Counties, NY
│
├─ Services
├─ How It Works
├─ Who We Serve
├─ Contact (Google Form)
│
└─ Footer (Company + Service Area)
```

Purpose:

* Explain what Expedition Plus does
* Capture leads
* SEO for local permit expediting

---

## 2. ACCESS LAYER – AUTHENTICATION & ROLES

```
/login
│
├─ Admin User
│   └─ Full CRM access
│
└─ Client User
    └─ Read-only access to own projects
```

**User Roles:**

* `admin`
* `client`

**Security Rules:**

* Admin can access everything
* Client can only access data linked to their own Client record
* Public pages require no login

---

## 3. CORE DOMAIN MODEL – CRM FOUNDATION

```
User
 ├─ role: admin | client
 └─ creates / views data
```

```
Client
 └─ has many → Projects
```

```
Project (CENTRAL OBJECT)
 ├─ belongs to → Client
 ├─ has many → Tasks
 ├─ has many → Notes
 ├─ has many → Time Logs
 ├─ has many → Documents
 ├─ has many → Checklists
 └─ linked to many → Associates
```

Everything below **must attach to a Project**.

---

## 4. OPERATIONAL MODULES (Extracted from Project Threads)

### 4.1 Tasks (from SOPs)

```
Task
 ├─ belongs to → Project
 ├─ type: road | office
 ├─ status: pending | in_progress | waiting_on_client | done
 ├─ optional → Associate
 └─ timestamps
```

**Task Templates (from SOP documents):**

```
SOP / Process Docs
 └─ become → Task Templates
     └─ applied to → Project
```

---

### 4.2 Notes (Internal History)

```
Note
 ├─ belongs to → Project
 ├─ written by → User
 └─ timestamped
```

Purpose:

* Communication log
* Internal context
* Audit trail

---

### 4.3 Time Logs (from Project Work Summary)

```
Time Log
 ├─ belongs to → Project
 ├─ date
 ├─ task description
 ├─ start / end time
 ├─ total hours
 ├─ type: road | office
 └─ notes
```

Purpose:

* Replace Excel time sheets
* Track real work performed
* Support billing / reporting

---

### 4.4 Associates (External Professionals)

```
Associate
 ├─ engineer
 ├─ architect
 ├─ surveyor
 ├─ village contact
 └─ consultant
```

```
Associate
 ├─ linked to → Projects
 └─ optionally assigned to → Tasks
```

Purpose:

* See everything tied to a specific engineer / architect
* Track dependencies and delays

---

### 4.5 Checklists (from Folder Checklists)

```
Checklist Template
 ├─ name (e.g. "Final Survey – New Dwelling")
 └─ items (line-by-line)
```

```
Checklist Template Item
 └─ one line from document
```

```
Project Checklist
 ├─ belongs to → Project
 └─ created from → Checklist Template
```

```
Project Checklist Item
 ├─ status: ok | required | n/a | pending
 ├─ note
 └─ belongs to → Project Checklist
```

Purpose:

* Turn static PDFs into live tracking tools
* Track inspection readiness and close-out progress

---

### 4.6 Documents (Uploaded Files)

```
Document
 ├─ belongs to → Project
 ├─ type (plans, VE letter, survey, form, etc.)
 ├─ filename / URL
 └─ notes
```

Purpose:

* Centralize all paperwork
* Tie documents to tasks and checklists

> **The CRM is not invented — it is extracted.**
> Every document, checklist, SOP, and spreadsheet already represents a feature.
> The system’s job is to make those **structured, searchable, and repeatable**.
